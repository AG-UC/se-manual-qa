SE-2256 — scan-adapter DomainOrig GTM-exclusion smoke

Static test page for the scan-adapter DomainOrigResolver fix (Jira: SE-2256 / CTS-4017; scan-adapter PR #23427).

Loads Google's gtag.js from www.googletagmanager.com so the Cookiebot scanner records cookies whose Initiator host is exactly the host the fix now excludes. After the fix, the resolver should fall back to tracker.ProviderDomain instead of attributing those cookies to www.googletagmanager.com.

Smoke target: after a Cookiebot dev scan of this page, no cookie in the resulting declaration should be attributed to www.googletagmanager.com as its provider. Cookies set by gtag.js should show their real third-party provider domain (or the first-party domain when applicable) — never the GTM host itself.

What's on this page

Just the gtag.js loader and a minimal dataLayer/gtag() bootstrap. G-DEMO12345 is a placeholder measurement id — the loader still fetches the bundle and runs the standard GA cookie initialisation (_ga, _gid, etc.). The scanner records the Initiator URL on each cookie set, which is what DomainOrigResolver matches against.

Out-of-scope on this page

  • No TikTok pixel / Meta pixel / Bing UET. Those are the user-facing symptoms in the SE-2256 ticket. Reproducing them synthetically requires a real GTM container that fires those tags; the canonical reproducer for that flavour of the bug is the production scan of vaccindirekt.se (see README).
  • No UC CMP. Cookiebot customers inject their own banner from the Cookiebot CDN once a CBID is bound to this URL.
  • No anchor links to sibling QA pages. Self-contained.
